# --- Ground truth + live estimate, sampled at a fixed rate -------------------
# In Lighthouse "as groundtruth" mode the crossing-beam position is NOT pushed
# to the estimator, so it never triggers estPosition. It must therefore be
# sampled time-based here. stateEstimate.* is the live (TDoA-driven) estimate,
# for on-drone comparison against the ground truth. outlierf.tdoaWin is the
# TDoA integrator outlier filter's open (1) / closed (0) state
# (outlierFilterTdoaState.isFilterOpen).
#
# The crossing beam only updates when all four sensors see both base stations,
# which is well under 50 Hz in practice, so this already oversamples it. Every
# sample costs ring buffer bandwidth that the candidate events need more.
on:fixedFrequency
50       # Hz
1        # mode: 1 = synchronous with stabilizer loop
lighthouse.x
lighthouse.y
lighthouse.z
lighthouse.delta
stateEstimate.x
stateEstimate.y
stateEstimate.z
outlierf.tdoaWin

# --- All TDoA anchor-pair candidates (needs param tdoaEngine.logCand > 0) -----
# The upstream, per-candidate event. Payload carries group/idA/idB/distanceDiff/
# isSelected, so no extra log variables are needed.
on:estTdoaCand

# --- Baseline: the single TDoA measurement the live algorithm selected --------
on:estTDOA

# --- Which flight this is, when examples/app_tdoa_flight is built in ----------
# Fires on each state/step change -- a few dozen times per run -- so the capture
# says which sequence it was and where each step began. An event, not a log
# variable in the block above: these change a handful of times per flight, so
# sampling them at 50 Hz would spend ring buffer bandwidth repeating a constant.
#
# Harmless on a build without the app: the uSD deck prints "Unknown event" and
# skips it, so this file still parses and usd.canLog still reads 1.
on:tdoaFlightStep
